## 关键词与权限级别

| 术语               | 含义                                                       |
| ------------------ | ---------------------------------------------------------- |
| **查看**     | 读取授权范围内的数据，不得修改。                           |
| **创建**     | 建立草稿或任务记录，不代表业务已经批准或生效。             |
| **编辑草稿** | 只修改尚未提交、尚未审批的业务数据。                       |
| **提交**     | 将草稿提交至下一审核或操作环节。                           |
| **审核**     | 对资料或业务条件进行检查并给出审核意见。                   |
| **批准**     | 对高风险业务作最终决定，使业务状态生效。                   |
| **执行**     | 执行已经满足前置条件的业务操作。                           |
| **撤回**     | 在下一角色尚未处理前，将本人提交的记录退回草稿。           |
| **退回**     | 审核或批准角色将记录退回上一环节补充。                     |
| **关闭**     | 受控终止业务，不删除既有记录。                             |
| **导出**     | 将查询结果导出为演示或审计文件。                           |
| **系统动作** | 由系统根据时间、状态或业务事件自动执行。                   |
| **硬隔离**   | 同一用户不得同时拥有或不得在同一业务实例上同时行使的权限。 |
| **双人控制** | 一个角色提出或执行，另一个角色审核或批准。                 |
| **后端阻断** | 权限必须在服务端校验，不能只隐藏前端按钮。                 |

## 1. 文档目的与设计边界

### 1.1 文档目的

本文档用于回答：

1. 每个业务角色的核心职责是什么；
2. 每个业务动作允许哪些角色执行；
3. 哪些角色必须被禁止执行该动作；
4. 权限与哪个业务流程和状态转换关联；
5. 操作前必须满足什么状态和业务条件；
6. 哪些操作需要审核、批准或双人控制；
7. 哪些角色只能查看、不能修改；
8. 越权尝试应如何阻断和记录。

### 1.2 本文档不冻结

本文件不冻结：

- 角色、权限和菜单的数据库表结构；
- Java 权限常量和注解名称；
- Sa-Token 或其他认证授权框架的具体配置；
- API 路径；
- 前端路由、菜单和按钮布局；
- 密码规则的具体数值；
- 真实企业人员任职、资质和岗位兼任结论；
- 企业 SOP 中未确认的特殊例外流程。

### 1.3 Demo 权限目标

Demo 至少必须能够证明：

- 不同账号登录后看到和执行的业务能力不同；
- 无权限操作被后端阻断；
- 采购员不能审核或批准首营；
- 收货员不能执行质量验收；
- 验收员不能修改采购订单；
- 质量管理员不能代替质量负责人作最终批准；
- 销售员不能修改库存质量结论或执行出库复核；
- 仓库管理员不能替代出库复核员；
- 系统管理员不能代替业务角色作质量或业务决定；
- 审计查看员只能读取，不得修改业务和审计数据；
- 敏感操作能够追溯到申请人、审核人、批准人、执行人和时间。

## 2. 权限设计原则

### 2.1 最小权限原则

每个角色只获得完成其岗位职责所必需的权限。

禁止：

- 给普通业务角色授予全局通配权限；
- 给系统管理员默认授予全部业务权限；
- 因为是 Demo 而跳过后端权限校验；
- 通过共享账号完成不同岗位操作。

### 2.2 基于角色并结合业务状态

权限判断至少同时考虑：

```text
用户是否登录
+
账号是否启用
+
是否拥有所需角色
+
业务对象当前状态是否允许
+
业务前置条件是否满足
+
是否存在本人提交、本人审核等职责冲突
```

仅有角色但状态不允许时，操作仍必须阻断。

### 2.3 质量管理独立性

- 质量负责人对药品质量管理具有最终质量裁决职责；
- 质量管理相关审核和批准不得由采购、销售、仓储或系统管理员代替；
- 质量管理员负责资料审核、规则审核、质量调查和处置建议；
- 质量负责人负责首营最终批准及重大质量处置批准；
- 质量管理员和验收员不得通过兼任采购、销售、收货、仓储等业务角色绕过职责分离；
- Demo 采用独立账号演示质量管理角色。

### 2.4 申请、审核、批准分离

以下高风险业务采用三段式或两段式控制：

```text
业务人员申请
→ 质量管理员审核
→ 质量负责人批准
```

或：

```text
业务人员执行
→ 独立复核员复核
```

同一用户不得在同一业务实例中同时完成申请和最终批准。

### 2.5 技术权限与业务权限分离

系统管理员负责：

- 账号维护；
- 技术配置；
- 权限配置的技术执行；
- Demo 环境维护；
- 备份恢复执行。

系统管理员不得：

- 审核或批准首营；
- 作出验收结论；
- 改变库存质量结论；
- 批准解除冻结或转不合格；
- 代替出库复核员复核；
- 修改或删除审计记录。

### 2.6 前端与后端双重控制

- 前端应隐藏或禁用无权限按钮；
- 后端必须再次校验权限、状态和职责冲突；
- 直接调用接口仍必须得到拒绝；
- 403 或业务阻断结果应进入安全或审计记录；
- 不得以“页面上看不到”为权限验收通过的唯一证据。

### 2.7 默认拒绝

未在本文档明确允许的敏感操作，默认拒绝。

### 2.8 法规映射控制与演示增强控制

本文档中的权限控制分为两类。

#### 2.8.1 法规映射控制

法规映射控制来源于公开监管要求，并用于把相关要求转化为 Demo 中可执行、可测试的权限边界，主要包括：

- 明确部门和岗位的职责、权限及相互关系；
- 质量负责人独立履行质量管理职责并具有质量裁决权；
- 质量管理部门职责不得由其他部门或人员代替；
- 质量管理部门负责供货单位、购货单位及相关人员合法资格审核；
- 质量管理部门负责计算机系统操作权限审核和质量管理基础数据管理；
- 收货、验收、储存、销售、出库复核和运输等岗位分别承担相应职责；
- 质量管理人员和验收人员按照适用要求保持岗位独立，不通过兼任其他业务工作绕过质量控制；
- 数据录入、修改和保存必须处于授权范围内，并保证数据真实、准确、安全和可追溯；
- 关键质量和经营操作必须形成真实、完整、准确、有效且可追溯的记录。

#### 2.8.2 演示增强控制

演示增强控制是为了让验证型 Demo 形成清晰、可测试、可审计的软件闭环而采用的工程控制，主要包括：

- 高风险角色分配采用申请、质量审核和最终批准的分层控制；
- 系统管理员与质量负责人、审计查看员使用独立演示账号；
- 同一用户在同一业务实例中不得同时完成申请、审核和最终批准；
- 备份恢复结果由第二角色复核证据；
- 敏感配置、数据重置和 Mock 交换终止采用二次确认或多人确认；
- 对越权失败、直接接口调用和职责冲突进行专门审计；
- 通过固定演示账号和权限验收场景证明后端权限真实生效。

上述演示增强控制不表示法规逐字要求所有企业必须采用相同审批级数、账号组合或技术实现。

正式商业化前，应结合目标企业的组织机构、人员资质、岗位制度、质量管理体系和 SOP，重新确认：

- 哪些角色可以由同一自然人兼任；
- 哪些角色必须在账号层硬隔离；
- 哪些操作需要两级或三级审批；
- 哪些技术操作需要质量部门审核；
- 哪些导出、配置和恢复操作需要二次认证或电子签名。

如果演示增强控制与真实企业经确认的制度不同，应通过正式范围和权限变更流程修订本文档，不得由开发人员或 AI 自行放宽控制。

## 3. 角色目录

### 3.1 系统管理员

| 项目     | 内容                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| 角色目标 | 维护 Demo 用户、角色、技术配置、演示环境和备份恢复任务。                                         |
| 允许     | 创建和停用演示账号、重置密码、按批准记录分配角色、查看系统运行信息、执行演示数据任务和备份恢复。 |
| 禁止     | 首营审核批准、客户资质审核、验收结论、质量事件调查结论、库存质量处置、销售确认、出库复核。       |
| 敏感边界 | 不得修改审计记录；不得给本人自行授予业务高风险角色；权限变更必须留痕。                           |

### 3.2 采购员

| 项目     | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 角色目标 | 维护采购侧基础资料，提交首营申请，创建和维护采购订单。           |
| 允许     | 创建供应商草稿、药品档案草稿、首营企业和首营品种申请、采购订单。 |
| 禁止     | 首营审核批准、收货、验收、质量处置、销售、出库复核。             |
| 敏感边界 | 不得修改已审核或已批准的质量结论；不得确认无有效准入的采购订单。 |

### 3.3 收货员

| 项目     | 内容                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 角色目标 | 根据采购订单核对实际到货、随货信息和运输信息，形成待验批次。                 |
| 允许     | 创建收货记录、登记到货差异、生成待验批次、扫描入库追溯码。                   |
| 禁止     | 修改采购订单核心数据、作出验收合格或不合格结论、形成合格库存、批准质量处置。 |
| 敏感边界 | 收货和验收必须分离；异常未处理时不得强制提交待验。                           |

### 3.4 验收员

| 项目     | 内容                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 角色目标 | 对收货药品逐批验收并记录验收结果。                                       |
| 允许     | 开始验收、录入检查结果、提交合格、部分合格或不合格结论、发起质量介入。   |
| 禁止     | 修改采购订单、修改收货来源、首营批准、库存冻结最终处置、销售和出库复核。 |
| 敏感边界 | 不得兼职其他业务工作；已完成验收结论的更正需要质量审核并保留原值。       |

### 3.5 质量管理员

| 项目     | 内容                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------- |
| 角色目标 | 审核主体和药品合法性，维护质量规则，调查质量事件并提出处置意见。                                                     |
| 允许     | 审核首营和客户资质、退回资料、冻结客户、审核计算机系统操作权限、调查质量事件、提出解除冻结或转不合格建议、查询追溯。 |
| 禁止     | 对本人提交事项作最终批准、代替质量负责人批准、修改采购和销售核心数据、执行出库复核。                                 |
| 敏感边界 | 可以提出质量决定，不得独立完成需要质量负责人批准的最终处置。                                                         |

### 3.6 质量负责人

| 项目     | 内容                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 角色目标 | 对首营企业、首营品种和重大质量处置作最终质量批准和裁决。                                             |
| 允许     | 批准或驳回首营、批准解除冻结、批准转不合格、退回质量调查、关闭重大质量事件、查看全链追溯和审计证据。 |
| 禁止     | 创建采购或销售订单、执行收货、验收、备货和出库复核、技术性分配用户角色。                             |
| 敏感边界 | 不得批准本人直接发起或直接调查且未经过独立审核的事项。                                               |

### 3.7 仓库管理员

| 项目     | 内容                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 角色目标 | 负责库位、验收合格入库、库存作业、备货、发运和签收记录。                           |
| 允许     | 确认库位、根据合格验收形成库存、备货、按批准业务产生库存流水、创建发运和签收记录。 |
| 禁止     | 修改验收结论、直接修改库存总数、改变质量结论、批准解除冻结、执行最终出库复核。     |
| 敏感边界 | 库存变化必须有业务来源和流水；不得操作锁定或过期库存。                             |

### 3.8 销售员

| 项目     | 内容                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 角色目标 | 维护客户资料草稿、创建销售订单并提交客户与库存校验。                           |
| 允许     | 创建客户资料草稿、提交客户资质审核、创建销售订单、选择候选批次、申请库存占用。 |
| 禁止     | 审核客户资质、修改库存质量结论、解除冻结、验收、出库复核、修改出库结果。       |
| 敏感边界 | 客户无效或范围不匹配时不得通过人工方式绕过校验。                               |

### 3.9 出库复核员

| 项目     | 内容                                                               |
| -------- | ------------------------------------------------------------------ |

## 9. 不相容职责与账号组合规则

### 9.1 硬隔离角色组合

默认情况下，同一演示账号不得同时拥有以下角色组合：

| 角色 A     | 角色 B                             | 原因                                 |
| ---------- | ---------------------------------- | ------------------------------------ |
| 采购员     | 质量管理员                         | 采购申请与质量审核必须分离           |
| 采购员     | 质量负责人                         | 首营申请与最终批准必须分离           |
| 收货员     | 验收员                             | 收货与质量验收必须分离               |
| 验收员     | 采购员、收货员、销售员、仓库管理员 | 验收岗位不得兼职其他业务工作         |
| 质量管理员 | 采购员、销售员、收货员、仓库管理员 | 质量管理职责不得由业务职责替代或混同 |
| 质量负责人 | 采购员、销售员、收货员、仓库管理员 | 质量最终裁决需保持独立               |
| 销售员     | 出库复核员                         | 销售创建与出库复核分离               |
| 仓库管理员 | 出库复核员                         | 备货和独立复核分离                   |
| 系统管理员 | 质量负责人                         | 技术管理与最终质量裁决分离           |
| 系统管理员 | 审计查看员                         | 系统维护与独立审计查看分离           |

### 9.2 同一业务实例的自我审批阻断

即使真实企业因人员规模需要一个自然人承担多个岗位，系统仍应阻断同一用户在同一业务实例中完成以下组合：

- 提交首营申请并最终批准；
- 审核首营申请并最终批准；
- 创建客户资料并审核其资质；
- 创建采购订单并执行收货或验收；
- 执行收货并作出验收结论；
- 提交验收结论并批准该结论的重大更正；
- 提交销售订单并执行出库复核；
- 备货并执行最终出库复核；
- 创建质量事件、提出处置建议并最终批准；
- 提出解除冻结并批准解除冻结；
- 申请高风险角色并批准自己的角色；
- 执行数据重置或恢复验证并独自确认结果有效。

### 9.3 Demo 账号规则

- 默认一个账号只绑定一个业务角色；
- 不使用共享账号；
- 不使用“万能业务管理员”账号；
- 系统管理员账号只用于技术管理；
- 质量负责人、出库复核员和审计查看员使用独立账号；
- 测试多角色组合时必须建立专门测试账号并标记用途；
- 账号和角色变化必须保留历史记录。

### 11.1 数据范围

首版为单企业、单仓 Demo，不实现复杂多组织数据权限，但仍需区分：

| 数据范围           | 适用角色                                                   |
| ------------------ | ---------------------------------------------------------- |
| 本人创建或负责业务 | 采购员、销售员                                             |
| 当前岗位待办业务   | 收货员、验收员、仓库管理员、出库复核员                     |
| 全部质量业务       | 质量管理员、质量负责人                                     |
| 全部技术配置       | 系统管理员                                                 |
| 全部审计只读       | 审计查看员                                                 |
| 追溯所需跨模块数据 | 质量管理员、质量负责人、审计查看员；其他角色仅查看必要摘要 |

### 11.2 字段级权限

| 数据类型               | 查看规则                                                                     | 修改规则                             |
| ---------------------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| 密码和认证凭据         | 任何角色不得查看明文                                                         | 只允许通过重置机制更新               |
| 身份证件和人员授权信息 | 质量管理员按审核需要查看；其他角色脱敏                                       | 来源业务角色补充，质量管理员审核     |
| 供应商和客户许可证     | 采购/销售维护草稿，质量角色完整查看                                          | 提交后只允许受控更正                 |
| 采购价格               | 采购员、审计查看员按授权查看                                                 | 采购员在允许状态修改                 |
| 客户销售信息           | 销售员看本人业务，质量和审计角色按需查看                                     | 销售员在草稿阶段修改                 |
| 验收结论               | 相关角色查看                                                                 | 验收员提交；完成后受控更正           |
| 库存数量               | 仓库管理员、质量管理员、质量负责人、销售员、出库复核员、审计查看员按职责查看 | 只能由受控业务流程和流水改变         |
| 质量结论与锁定状态     | 质量、仓库、复核等必要角色查看                                               | 质量流程控制，不允许普通业务角色修改 |
| 审计日志               | 质量负责人、质量管理员、审计查看员查看                                       | 全部角色禁止修改删除                 |
| Mock 请求与回执        | 质量、系统、审计角色查看；业务角色看摘要                                     | 由系统生成，不允许人工改成功         |
| 备份位置和技术日志     | 系统管理员、审计查看员                                                       | 系统管理员受控维护                   |

### 11.3 导出控制

- 导出完整资质、审计、追溯和客户去向数据必须有明确权限；
- 导出应记录操作人、时间、筛选条件、记录数量和导出用途；
- 身份证号码、联系方式等应按最小必要原则脱敏；
- 普通业务角色不得导出全量审计日志；
- 导出文件必须标识“Demo 数据”；
- 广东 Mock 回执导出必须明确标识“模拟结果，非真实监管回执”。

## 12. 审计与越权失败记录

### 12.1 必须审计的成功操作

至少包括：

- 登录、退出、登录失败；
- 用户启用、停用、密码重置；
- 角色申请、审核、批准和分配；
- 药品、供应商、客户关键字段变化；
- 首营提交、审核、批准、驳回和失效；
- 客户资质审核、冻结、解除冻结和失效；
- 采购订单确认、关闭和受控更正；
- 收货、异常处理和待验生成；
- 验收开始、结论和受控更正；
- 入库、库存占用、释放、扣减和调整；
- 销售提交、客户校验和批次分配；
- 出库复核、出库、发运、签收和运输异常；
- 质量事件、库存冻结、解除冻结和转不合格；
- 追溯查询和敏感数据导出；
- 追溯码核验、Mock 请求、失败、重试和终止；
- 演示数据初始化、重置；
- 备份、恢复和验证。

### 12.2 必须记录的失败或阻断

至少包括：

- 未登录访问；
- 账号停用；
- 无角色权限；
- 业务状态不允许；
- 同一用户违反职责分离；
- 首营或客户准入失败；
- 待验、冻结、不合格或过期库存被尝试销售；
- 超量占用或负库存风险；
- 复核未通过仍尝试出库；
- 重复追溯码或信息不一致；
- Mock 上传失败后人工改成功；
- 非 Demo 环境执行数据重置；
- 无有效备份却标记恢复成功；
- 修改或删除审计记录的尝试。

### 12.3 审计记录不可变规则

- 普通用户不能修改或删除审计记录；
- 系统管理员也不得直接编辑审计业务内容；
- 审计更正只能追加说明，不能覆盖原记录；
- 审计查询和导出本身也应被记录；
- 日志不得包含明文密码、完整密钥或不必要的敏感信息。

## 14. 实现约束

### 14.1 后端必须强制校验

后续代码实现必须保证：

- Controller 或权限拦截层验证登录和粗粒度权限；
- Service 验证业务状态、数据范围和职责冲突；
- Mapper 或数据库不能成为绕过业务权限的公开入口；
- 关键权限不能仅依赖前端按钮；
- 失败时事务不得产生部分业务结果。

### 14.2 权限粒度

权限应以“业务动作”为核心，不只以菜单为核心。

例如：

```text
首营企业：创建
首营企业：提交
首营企业：审核
首营企业：批准
首营企业：失效
```

不得只设计：

```text
首营管理菜单：可见
```

### 14.3 不提前冻结代码值

本文档中的角色和动作名称是业务名称。

后续可由数据库和代码设计确定：

- 角色代码；
- 权限代码；
- API 路径；
- 注解表达；
- Sa-Token 权限字符串；
- 数据库表结构。

### 14.4 禁止通配业务权限

除受控审计查询外，不应为业务角色提供类似：

```text
business:*
quality:*
inventory:*
```

的全量权限。

### 14.5 超级管理员边界

即使技术框架存在超级管理员能力：

- 只允许在受控开发或故障恢复环境使用；
- 正常 Demo 业务流程不得使用超级管理员完成业务；
- 超级管理员绕过业务权限的动作不计入业务验收通过；
- 超级管理员操作必须单独记录。

## 15. 实施阶段待确认事项

以下问题不改变本版核心权限边界，应在真实企业或对应开发 Goal 中确认：

1. 真实目标企业中质量负责人、质量管理部门负责人是否为同一自然人；
2. 真实企业是否允许仓库管理员同时负责发运和签收登记；
3. 客户、供应商和药品基础资料是否由专职资料员维护；
4. 采购订单确认是否增加采购主管角色；
5. 客户解除冻结的重大争议判定标准；
6. 验收结论更正的重大程度和可更正范围；
7. 审计查看员是否允许导出含客户去向的完整追溯报告；
8. 是否需要增加独立信息管理员角色；
9. 是否需要增加企业负责人作为重大事项查看或批准角色；
10. 真实人员兼任时，哪些组合在账号层硬阻断、哪些只做实例级阻断；
11. 后续正式系统是否引入临时授权、权限有效期、二次认证和电子签名；
12. 受控更正首版实际开放哪些业务对象；
13. `sys_role_assignment` 在 M1 是否完整实现，或先以固定种子账号演示；
14. 质量阻断占用最终采用 `BLOCKED_BY_QUALITY` 还是直接 `RELEASED` 的数据库代码；
15. Mock 终止审批是否在真实企业 SOP 中需要质量负责人追加批准。

以下事项已经确定，不再作为待确认：

- 首版人工库存数量调整不开放；
- SM-08 不包含冻结；
- SM-14 独立管理冻结、解除和转不合格；
- SM-15 与 SM-16 分离；
- Mock 失败不得人工改成功；
- 备份失败和恢复失败记录不得删除。

### 16.2 官方监管背景

权限设计方向参考以下官方文件：

1. 《药品经营质量管理规范》：

   - 企业应明确部门和岗位职责、权限及相互关系；
   - 质量负责人独立履职并具有质量裁决权；
   - 质量管理部门职责不得由其他部门或人员履行；
   - 质量管理部门负责供货单位、购货单位及相关人员合法资格审核；
   - 质量管理部门负责计算机系统操作权限审核和质量管理基础数据管理；
   - 质量管理和验收人员应在职在岗，不得兼职其他业务工作；
   - 数据录入、修改和保存必须符合授权范围；
   - 收货、验收和出库复核分别形成受控岗位和记录。
2. 《药品经营和使用质量监督管理办法》：

   - 药品批发企业应具备与经营范围相适应的质量管理机构和人员；
   - 经营全过程应落实质量管理责任。
3. 《广东省药品监督管理局药品批发企业储存运输管理若干规定》：

   - 质量管理部门应充分行使质量管理职能，其职责不得由其他部门或人员履行；
   - 信息管理系统应覆盖收货、验收、储存、出库复核、运输、签收和全过程追溯；
   - 企业应设置质量管理、储存运输和信息管理等相适应的部门和岗位。
