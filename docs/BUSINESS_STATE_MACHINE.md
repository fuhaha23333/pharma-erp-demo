## 0. v1.2 第一阶段执行 Profile

`PHASE1_CURRENT_API` 对 SM-02 使用以下已经实现并获批准的简化状态机：

```text
DRAFT
  → UNDER_REVIEW
  → APPROVED
  → REJECTED

REJECTED
  → UNDER_REVIEW
```

| 当前状态 | 动作 | 下一状态 | 权限与守卫 |
| --- | --- | --- | --- |
| `DRAFT` / `REJECTED` | 编辑供应商、资质和附件 | 状态不变 | `SUPPLIER_WRITE` |
| `DRAFT` / `REJECTED` | 提交审核 | `UNDER_REVIEW` | `SUPPLIER_SUBMIT`；营业执照、匹配供应商类型的许可证和授权文件均有效且有附件 |
| `UNDER_REVIEW` | 审核通过 | `APPROVED` | `SUPPLIER_REVIEW`；审核人不能是提交人 |
| `UNDER_REVIEW` | 审核驳回 | `REJECTED` | `SUPPLIER_REVIEW`；审核人不能是提交人；驳回原因必填 |

每次重新提交生成新的审核轮次和不可变资质快照。原 SM-02 的两级审核状态继续作为完整 M1 后续目标，本次前端只展示上述实际状态，不伪造尚未实现的审批节点。

## 1. 文档目的与边界

### 1.1 文档目的

本文档回答：

1. 业务对象当前处于什么状态；
2. 哪个动作可以触发状态转换；
3. 哪个角色可以执行该动作；
4. 转换前必须满足哪些业务条件；
5. 哪些转换必须被阻断；
6. 转换成功后应形成什么业务结果；
7. 哪些信息必须进入状态历史和审计；
8. 不同状态机之间如何联动但不混淆。

### 1.2 状态机不等于数据库字段

本文档冻结业务语义，不直接冻结：

- 数据库列名；
- Java Enum 类名和代码值；
- API 路径；
- 页面按钮；
- ORM 注解；
- 通用工作流模型。

数据库可以为了事务和查询增加内部技术状态，但必须：

- 能映射回本文档的业务状态；
- 不改变本文档的业务结果；
- 不允许绕过本文档定义的守卫；
- 在 `DATABASE_DESIGN_DEMO.md` 中明确标注技术细分状态。

### 1.3 业务状态与派生条件

以下内容通常是派生条件，不必强制保存为独立状态记录：

- Mock 任务“未生成”可表示任务记录尚不存在；
- 库存“可用”可由合格、未过期、未冻结和可用数量大于零派生；
- 药品或客户的“当前有效”需要同时考虑状态和有效期；
- 近效期是预警条件，不是质量结论。

## 2. 通用状态转换规则

### 2.1 必须记录的状态变化信息

所有状态转换至少记录：

- 业务对象类型和业务编号；
- 操作人或系统动作标识；
- 操作时间；
- 原状态；
- 新状态；
- 触发动作；
- 操作原因；
- 关联业务记录；
- 审核、批准或复核信息；
- 操作结果；
- 失败或阻断原因。

### 2.2 通用禁止规则

禁止：

- 直接执行 SQL 修改状态绕过业务流程；
- 删除状态历史；
- 覆盖原审批意见；
- 把失败状态无痕改为成功；
- 先写成功状态、后补业务结果；
- 在事务部分失败时保留目标状态；
- 由系统管理员代替业务角色作质量结论；
- 使用共享账号完成申请、审核和批准。

### 2.3 后端守卫

状态转换必须同时校验：

```text
用户已登录
+
账号可用
+
角色和权限允许
+
来源状态允许
+
业务前置条件成立
+
不存在自我审批或不相容职责
+
事务内数据仍满足条件
```

前端隐藏按钮不能替代后端校验。

### 2.4 失败处理

状态转换失败时：

- 业务对象保持原状态；
- 不产生部分库存、占用、出库或质量结果；
- 记录失败原因；
- 必要时记录安全或审计事件；
- 可重试动作必须保留原失败记录。

# 3. M1 全国核心状态机

## SM-01 药品档案状态

### 业务对象

药品稳定档案，不包含具体批号、库存和具体追溯码。

### 状态

```text
草稿
→ 待完善
→ 可提交首营
```

受控停用与恢复：

```text
待完善/可提交首营
→ 停用

停用
→ 待完善/可提交首营
```

### 转换规则

| 当前状态          | 动作         | 下一状态   | 执行角色   | 守卫条件                     |
| ----------------- | ------------ | ---------- | ---------- | ---------------------------- |
| 草稿              | 保存基础资料 | 待完善     | 采购员     | 药品编码不存在重复           |
| 待完善            | 完成资料检查 | 可提交首营 | 质量管理员 | 必填资料完整、明显矛盾已处理 |
| 待完善/可提交首营 | 停用         | 停用       | 质量管理员 | 填写原因并评估下游影响       |
| 停用              | 恢复维护     | 待完善     | 质量管理员 | 资料需要重新检查             |
| 停用              | 恢复可提交   | 可提交首营 | 质量管理员 | 资料仍完整有效               |

### 规则

- 药品档案达到“可提交首营”不等于首营品种已批准；
- 首营品种未批准时不得采购；
- 停用药品不得新增采购和销售；
- 已被业务引用的药品档案不得删除；
- 关键字段更正必须保留前后值。

### 禁止转换

```text
草稿/待完善
→ 已批准首营

可提交首营
→ 合格库存
```

## SM-02 首营企业状态

### 状态

```text
草稿
→ 待质量审核
→ 待质量负责人批准
→ 已批准
```

退回、撤回和驳回：

```text
待质量审核
→ 草稿            撤回，审核尚未开始

待质量审核
→ 退回补充

退回补充
→ 待质量审核

待质量审核
→ 已驳回

待质量负责人批准
→ 已驳回
```

失效：

```text
已批准
→ 已失效
```

### 转换规则

| 当前状态         | 动作           | 下一状态         | 执行角色            | 守卫条件               |
| ---------------- | -------------- | ---------------- | ------------------- | ---------------------- |
| 草稿             | 提交审核       | 待质量审核       | 采购员              | 资料齐全               |
| 待质量审核       | 撤回           | 草稿             | 采购员              | 质量管理员尚未处理     |
| 待质量审核       | 退回补充       | 退回补充         | 质量管理员          | 退回意见完整           |
| 退回补充         | 重新提交       | 待质量审核       | 采购员              | 补充资料完成           |
| 待质量审核       | 审核通过       | 待质量负责人批准 | 质量管理员          | 合法资格和范围核验完成 |
| 待质量审核       | 驳回           | 已驳回           | 质量管理员          | 存在不能补正的问题     |
| 待质量负责人批准 | 批准           | 已批准           | 质量负责人          | 质量审核完成           |
| 待质量负责人批准 | 驳回           | 已驳回           | 质量负责人          | 最终意见完整           |
| 已批准           | 资质到期或失效 | 已失效           | 系统动作/质量管理员 | 到期、撤销或关键变化   |

### 规则

- 未批准或已失效供应商不得确认采购订单；
- 采购员不得审核或批准本人申请；
- 质量管理员不得代替质量负责人最终批准；
- 重新审核应创建新版本或保留完整历史。

## SM-03 首营品种状态

### 业务边界

首营品种按：

```text
药品
+
拟供货供应商
```

建立业务关系。

### 状态

```text
草稿
→ 待质量审核
→ 待质量负责人批准
→ 已批准
```

异常：

```text
待质量审核
→ 退回补充/已驳回

待质量负责人批准
→ 已驳回

已批准
→ 已失效
```

### 转换规则

| 当前状态         | 动作     | 下一状态         | 执行角色            | 守卫条件                           |
| ---------------- | -------- | ---------------- | ------------------- | ---------------------------------- |
| 草稿             | 提交审核 | 待质量审核       | 采购员              | 药品可提交首营、供应商有效         |
| 待质量审核       | 退回补充 | 退回补充         | 质量管理员          | 意见完整                           |
| 退回补充         | 重新提交 | 待质量审核       | 采购员              | 补充完成                           |
| 待质量审核       | 审核通过 | 待质量负责人批准 | 质量管理员          | 药品合法性、供货范围核验完成       |
| 待质量审核       | 驳回     | 已驳回           | 质量管理员          | 存在不能补正的问题                 |
| 待质量负责人批准 | 批准     | 已批准           | 质量负责人          | 审核意见完整                       |
| 待质量负责人批准 | 驳回     | 已驳回           | 质量负责人          | 最终意见完整                       |
| 已批准           | 触发失效 | 已失效           | 系统动作/质量管理员 | 药品停用、供应商失效或关键资料变化 |

### 规则

- 相同药品由不同供应商供货时，分别建立首营品种关系；
- 未批准首营品种不得确认采购订单；
- 关键资料变化后不得继续沿用旧批准结论。

## SM-04 客户资质状态

### 状态

```text
草稿
→ 待审核
→ 有效
```

退回与驳回：

```text
待审核
→ 退回补充/已驳回

退回补充
→ 待审核
```

冻结、恢复和失效：

```text
有效
→ 冻结

冻结
→ 有效

有效/冻结
→ 已失效
```

### 转换规则

| 当前状态  | 动作     | 下一状态 | 执行角色            | 守卫条件                                     |
| --------- | -------- | -------- | ------------------- | -------------------------------------------- |
| 草稿      | 提交审核 | 待审核   | 销售员              | 资质、范围和人员资料齐全                     |
| 待审核    | 退回补充 | 退回补充 | 质量管理员          | 退回原因完整                                 |
| 退回补充  | 重新提交 | 待审核   | 销售员              | 补充完成                                     |
| 待审核    | 审核通过 | 有效     | 质量管理员          | 合法性、范围和人员资格有效                   |
| 待审核    | 驳回     | 已驳回   | 质量管理员          | 存在不能补正的问题                           |
| 有效      | 风险冻结 | 冻结     | 质量管理员          | 风险原因完整                                 |
| 冻结      | 解除冻结 | 有效     | 质量管理员          | 风险消除、资质仍有效；重大争议按权限矩阵裁决 |
| 有效/冻结 | 资质失效 | 已失效   | 系统动作/质量管理员 | 到期、撤销或主体变化                         |

### 规则

- 销售确认和出库前必须动态校验；
- 冻结、已失效和已驳回客户不得销售；
- 销售员不得修改质量审核结论；
- 解除冻结不能绕过当前有效期和范围检查。

## SM-05 采购订单状态

### 状态

```text
草稿
→ 已确认
→ 部分收货
→ 已完成
```

关闭：

```text
草稿
→ 已关闭

已确认
→ 已关闭
```

### 转换规则

| 当前状态        | 动作         | 下一状态 | 执行角色 | 守卫条件                           |
| --------------- | ------------ | -------- | -------- | ---------------------------------- |
| 草稿            | 确认订单     | 已确认   | 采购员   | 首营企业、首营品种、药品档案均有效 |
| 草稿            | 关闭草稿     | 已关闭   | 采购员   | 无下游记录                         |
| 已确认          | 受控关闭     | 已关闭   | 采购员   | 尚无收货记录                       |
| 已确认          | 完成部分收货 | 部分收货 | 系统动作 | 已收数量小于订单数量               |
| 已确认/部分收货 | 全部收货     | 已完成   | 系统动作 | 已收数量达到订单数量               |
| 部分收货        | 终止剩余数量 | 已完成   | 采购员   | 原因完整，已收部分保留             |

### 规则

- 采购订单不能直接形成库存；
- 已产生收货记录后不能直接关闭；
- 已确认订单核心字段不能无痕修改；
- 完成只表示采购来源闭合，不表示药品已验收合格。

## SM-06 收货状态

### 状态

```text
草稿
→ 收货中
→ 已收货
→ 待验
```

异常处理：

```text
收货中
→ 待处理
→ 收货中
```

取消：

```text
草稿/收货中
→ 已取消
```

### 转换规则

| 当前状态    | 动作             | 下一状态 | 执行角色 | 守卫条件                       |
| ----------- | ---------------- | -------- | -------- | ------------------------------ |
| 草稿        | 开始收货         | 收货中   | 收货员   | 货物实际到达、采购订单可收货   |
| 收货中      | 登记异常         | 待处理   | 收货员   | 数量、包装、运输或随货异常完整 |
| 待处理      | 一般差异处理完成 | 收货中   | 收货员   | 涉及质量风险时质量管理员已介入 |
| 收货中      | 完成收货         | 已收货   | 收货员   | 票、账、货核对完成             |
| 已收货      | 生成验收任务     | 待验     | 系统动作 | 批号、数量等必要信息完整       |
| 草稿/收货中 | 取消             | 已取消   | 收货员   | 尚无验收记录                   |

### 规则

- 收货不等于验收；
- 收货员不得作合格、不合格结论；
- 待处理未解决时不得生成待验；
- 进入验收后，来源收货数据只能受控更正。

## SM-07 验收状态

待验收

```

质量介入：

```

### 转换规则

| 当前状态   | 动作         | 下一状态   | 执行角色   | 守卫条件                       |
| ---------- | ------------ | ---------- | ---------- | ------------------------------ |
| 待验收     | 开始验收     | 验收中     | 验收员     | 收货来源有效                   |
| 验收中     | 请求质量介入 | 待质量处理 | 验收员     | 存在无法直接判断的问题         |
| 待质量处理 | 给出处理意见 | 验收中     | 质量管理员 | 意见完整                       |
| 验收中     | 提交合格     | 合格       | 验收员     | 检查项通过                     |
| 验收中     | 提交部分合格 | 部分合格   | 验收员     | 合格数与不合格数合计等于验收数 |
| 验收中     | 提交不合格   | 不合格     | 验收员     | 不合格事项和处置措施完整       |

### 规则

- 必须逐批验收；
- 收货员不得执行验收结论；
- 过期批次不得判定合格；
- 部分合格只允许合格数量进入合格入库；
- 完成结论后的更正必须经过受控更正，不覆盖原结论。

## SM-08 批号库存质量结论

### 状态边界

SM-08 只表达质量结论：

```text
待验
→ 合格

待验
→ 不合格

合格
→ 过期

合格
→ 不合格
```

其中“合格→不合格”必须由 SM-14 的质量处置批准触发。

**冻结不属于 SM-08 的质量结论状态。**
冻结由 SM-14 独立表达；因此可以出现：

```text
质量结论 = 合格
且
冻结状态 = 冻结
```

### 规则

- 待验不进入可销售库存；
- 不合格和过期不得销售和出库；
- 过期不得恢复为合格；
- 冻结解除只解除限制，不自动改变质量结论；
- 质量状态转换必须形成库存流水和审计证据；
- 不得通过直接修改 `quality_status` 完成转换。

### 禁止转换

```text
待验
→ 冻结

不合格/过期
→ 合格
```

## SM-09 库存占用状态

### 业务语义

“可用”是派生条件，不一定对应一条占用记录。

### 状态

```text
可用
→ 已占用
→ 已出库
```

释放与质量阻断：

```text
已占用
→ 已释放

已占用
→ 质量阻断
```

### 转换规则

| 当前状态 | 动作              | 下一状态 | 执行角色 | 守卫条件                       |
| -------- | ----------------- | -------- | -------- | ------------------------------ |
| 可用     | 创建占用          | 已占用   | 系统动作 | 合格、未过期、未冻结、数量充足 |
| 已占用   | 主动释放/订单关闭 | 已释放   | 系统动作 | 尚未出库                       |
| 已占用   | 质量冻结影响      | 质量阻断 | 系统动作 | 对应库存进入活动冻结           |
| 已占用   | 完成出库          | 已出库   | 系统动作 | 出库复核通过且扣减成功         |

### 规则

- 占用不能超过可用数量；
- 占用不等于实际库存扣减；
- 质量阻断后原占用不能继续出库，应重新分配；
- 出库失败必须保持或释放占用，不得标记已出库；
- 并发占用必须由事务和数据库锁控制。

# 4. 销售、出库与运输状态机

## SM-10 销售订单状态

### 主流程

```text
草稿
→ 待客户校验
→ 已确认
→ 待分配批次
→ 已分配批次
→ 待出库复核
→ 已完成
```

人工确认、驳回和关闭：

```text
待客户校验
→ 待人工确认
→ 已确认/已驳回

待客户校验
→ 已驳回

草稿/已确认
→ 已关闭
```

批次失效或质量阻断：

```text
已分配批次/待出库复核
→ 待分配批次
```

### 规则

- 客户资质有效、范围匹配后才能确认；
- 销售员不得人工覆盖失败校验；
- 批次必须合格、未过期、未冻结且数量充足；
- 进入复核后核心数据原则上不可修改；
- 批次被质量阻断时必须释放占用并退回重新分配；
- 已出库业务不得通过关闭订单抹除。

## SM-11 出库复核状态

### 状态

```text
待复核
→ 复核中
→ 复核通过
→ 已出库
```

失败与重新提交：

```text
复核中
→ 复核不通过

复核不通过
→ 待复核
```

### 转换规则

| 当前状态   | 动作           | 下一状态   | 执行角色          | 守卫条件                                     |
| ---------- | -------------- | ---------- | ----------------- | -------------------------------------------- |
| 待复核     | 开始复核       | 复核中     | 出库复核员        | 订单、批次和占用有效                         |
| 复核中     | 提交通过       | 复核通过   | 出库复核员        | 客户、药品、批号、效期、数量和质量条件均通过 |
| 复核中     | 提交不通过     | 复核不通过 | 出库复核员        | 失败原因完整                                 |
| 复核不通过 | 纠正并重新提交 | 待复核     | 仓库管理员/销售员 | 问题已纠正                                   |
| 复核通过   | 执行出库       | 已出库     | 系统动作          | 库存扣减、占用消费和流水同一事务成功         |

### 规则

- 出库复核员不得修改销售订单源数据；
- 复核失败不能出库和发运；
- 复核通过但库存事务失败时不得标记已出库；
- 每次复核尝试独立保存，不覆盖失败记录。

# 5. M2 质量事件与广东增强状态机

| 已创建     | 开始调查     | 调查中     | 质量管理员          | 能定位药品、批号或业务范围 |

- 关闭质量事件不删除历史；
- 已售客户影响只展示和记录，首版不自动生成召回流程。

## SM-14 库存冻结与质量处置状态

### 状态边界

SM-14 是独立于 SM-08 质量结论的限制状态。

### 状态

```text
未锁定
→ 冻结
```

解除冻结：

```text
冻结
→ 待解除审批
→ 已解除
```

转不合格：

```text
冻结
→ 待转不合格审批
→ 已转不合格
```

审批退回：

```text
待解除审批/待转不合格审批
→ 冻结
```

### 规则

- 紧急冻结可由质量管理员执行；
- 冻结立即阻断新销售占用和出库；
- 已有占用必须释放或转为质量阻断；
- 解除冻结由质量管理员提出、质量负责人批准；
- 转不合格由质量管理员提出、质量负责人批准；
- 已解除只解除限制，SM-08 质量结论仍为合格；
- 已转不合格必须同步把 SM-08 质量结论转为不合格；
- 不得通过删除冻结记录解除限制。

## SM-15 广东追溯码本地核验状态

### 状态边界

SM-15 只负责：

- 本地采集；
- 药品、批号、数量和业务关系核验；
- 重复码核验；
- 失败后的纠正与重新核验；
- 未使用码作废；
- 入库、出库业务关联。

SM-15 **不包含**待上传、上传中、上传成功、上传失败、重试和终止；这些属于 SM-16。

### 状态

```text
未采集
→ 待核验
→ 核验通过
```

失败、重试和作废：

```text
待核验
→ 核验失败

核验失败
→ 待核验

未采集/核验失败
→ 已作废
```

### 转换规则

| 当前状态        | 动作           | 下一状态 | 执行角色                 | 守卫条件                               |
| --------------- | -------------- | -------- | ------------------------ | -------------------------------------- |
| 未采集          | 扫描或录入     | 待核验   | 收货员/验收员/出库复核员 | `GD_DEMO_PROFILE` 且药品启用码级管理 |
| 待核验          | 本地核验成功   | 核验通过 | 系统动作                 | 码唯一，药品、批号、数量和业务关系一致 |
| 待核验          | 本地核验失败   | 核验失败 | 系统动作                 | 保存失败代码和原因                     |
| 核验失败        | 纠正后重新提交 | 待核验   | 原业务环节角色           | 来源数据已纠正                         |
| 未采集/核验失败 | 作废           | 已作废   | 质量管理员               | 码未被有效业务使用，原因完整           |

### 规则

- 追溯码必须唯一；
- 重复码必须阻断；
- 药品、批号、数量或业务关系不一致必须阻断；
- 核验失败不得人工直接改为核验通过；
- 重新核验必须保留原失败事件；
- 已作废码不得重新用于入库或出库；
- 本地核验通过不等于 Mock 上传成功；
- 未启用广东 Profile 或码级管理时，不强制执行码级状态机。

## SM-16 广东追溯码 Mock 交换状态

### 状态边界

“未生成”表示 Mock 任务记录尚不存在。有效入库或出库业务事件触发后，创建任务并进入“待上传”。

### 状态

```text
未生成
→ 待上传
→ 上传中
→ 上传成功
```

失败、重试和终止：

```text
上传中
→ 上传失败

上传失败
→ 待重试

待重试
→ 上传中

待上传/上传失败/待重试
→ 已终止
```

### 转换规则

| 当前状态               | 动作           | 下一状态 | 执行角色                | 守卫条件                           |
| ---------------------- | -------------- | -------- | ----------------------- | ---------------------------------- |
| 未生成                 | 生成 Mock 任务 | 待上传   | 系统动作                | 本地业务事件完成且需要广东码级交换 |
| 待上传                 | 执行上传       | 上传中   | 系统动作/系统管理员触发 | Mock 服务启用                      |
| 上传中                 | 获得成功回执   | 上传成功 | Mock 适配器             | 回执明确成功                       |
| 上传中                 | 获得失败或超时 | 上传失败 | Mock 适配器             | 保存失败原因和回执                 |
| 上传失败               | 标记待重试     | 待重试   | 系统动作/系统管理员     | 失败原因存在                       |
| 待重试                 | 执行重试       | 上传中   | 系统动作/系统管理员     | 新增重试尝试                       |
| 待上传/上传失败/待重试 | 终止任务       | 已终止   | 系统管理员              | 质量管理员审核、终止原因完整       |

### 规则

- 每次上传和重试保存独立尝试；
- 重试不得覆盖原失败记录；
- 上传失败不得人工直接改为上传成功；
- 已终止任务不得继续上传或重试；
- Mock 上传成功不得描述为真实监管平台成功；
- 外部调用不得长时间持有库存事务锁；
- 本状态机不连接真实国家、广东、第三方或医保平台。

# 7. 状态机联动规则

## 7.1 准入与采购

```text
SM-02 首营企业 = 已批准
+
SM-03 首营品种 = 已批准
+
SM-01 药品档案 = 可提交首营
→
SM-05 采购订单允许确认
```

任一条件失效时，阻断新采购。

## 7.2 收货、验收与库存

```text
SM-05 采购订单已确认
→ SM-06 收货
→ SM-07 验收
→ SM-08 合格库存
```

禁止：

```text
采购订单
→ 直接增加库存

收货完成
→ 直接形成合格库存

待验
→ 无验收结论形成库存
```

## 7.3 销售与出库

```text
SM-04 客户资质 = 有效
+
SM-08 质量结论 = 合格
+
SM-14 = 未锁定/已解除
+
未过期
+
可用数量充足
→
SM-09 允许占用
→
SM-11 复核通过
→
完成出库
```

## 7.4 质量事件联动

```text
SM-13 创建质量事件
→ SM-14 冻结
→ 释放或质量阻断 SM-09 占用
→ 阻断 SM-10/SM-11 后续动作
```

处置批准后：

```text
SM-14 已解除
→ SM-08 仍为合格

或

SM-14 已转不合格
→ SM-08 转为不合格
```

## 7.5 广东追溯联动

```text
SM-15 本地核验通过
→ 允许对应码级业务继续

有效入库或出库事件完成
→ SM-16 生成 Mock 任务
```

SM-16 失败不回滚已经真实完成的本地业务事实，但必须：

- 保存失败；
- 提供重试或终止；
- 不伪装为上传成功。

# 8. 禁止状态跳转清单

| 禁止跳转                             | 原因                         |
| ------------------------------------ | ---------------------------- |
| 药品档案可提交首营 → 首营品种已批准 | 缺少质量审核和质量负责人批准 |

| 收货完成 → 合格库存                 | 缺少逐批验收结论             |

| 不合格/过期 → 合格                  | 不允许无审批恢复             |

| 客户冻结/失效 → 销售订单已确认      | 客户准入失败                 |
| 库存未占用 → 已出库                 | 缺少批次分配和占用           |
| 复核不通过 → 已出库                 | 未通过独立复核               |
| 本地核验失败 → 核验通过             | 必须纠正后重新核验           |
| Mock 上传失败 → 上传成功            | 必须执行新尝试并获得成功回执 |
| 备份失败 → 验证成功                 | 缺少有效备份                 |
| 恢复核对失败 → 验证成功             | 核对证据不完整               |

# 9. 状态历史与审计要求

## 9.1 必须记录成功转换

至少包括：

- 首营提交、审核、批准、驳回和失效；
- 客户审核、冻结、解除和失效；
- 采购确认、部分收货、完成和关闭；
- 收货开始、异常、完成和待验；
- 验收开始、质量介入和结论；
- 合格入库、过期和转不合格；
- 库存占用、释放、质量阻断和出库；
- 出库复核通过、失败和重新复核；
- 发运、签收和运输异常；
- 质量事件调查、审批、执行和关闭；
- 追溯码核验、失败、重试和作废；
- Mock 生成、上传、失败、重试和终止；
- 演示任务、备份和恢复验证。

## 9.2 必须记录失败或阻断

至少包括：

- 来源状态不允许；
- 权限不足；
- 自我审批；
- 资质或首营失效；
- 数量不足或并发冲突；
- 冻结、不合格或过期库存被尝试销售；
- 复核失败仍尝试出库；
- 重复码或码信息不一致；
- Mock 失败后人工改成功；
- 非 Demo 环境执行重置；
- 无有效备份标记恢复成功；
- 直接修改状态或删除历史的尝试。

## 9.3 不可变原则

- 状态历史只追加；
- 失败记录不覆盖；
- 审批意见保留原值；
- 更正记录引用原业务对象和原状态；
- 系统管理员不能编辑业务审计内容；
- 日志不得包含明文密码和密钥。
